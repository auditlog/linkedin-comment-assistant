# Asystent komentarzy LinkedIn: projekt (2026-11-09)

## Po co

Użytkownik komentuje posty na LinkedInie, często anglojęzyczne, a myśli i pisze po polsku. Najwięcej czasu traci na:
1. zrozumienie posta (tłumaczenie),
2. wymyślenie komentarza pasującego do kontekstu,
3. tłumaczenie własnego tekstu na angielski i sprawdzenie poprawności,
4. powrót na LinkedIna: po wizycie w DeepL lub ChatGPT feed się przewija i post znika z widoku.

**Sukces:** jedno miejsce obok LinkedIna, bez przełączania kart. Użytkownik rozumie post, ma pomysł, dostaje poprawny komentarz i wie, co publikuje.

**Porażka, nawet jeśli wszystko technicznie działa:** generyczne „AI-owe” komentarze („Great post, thanks for sharing!”) albo cokolwiek publikowane bez kliknięcia użytkownika.

## Decyzje

| Decyzja | Wybór | Dlaczego |
|---|---|---|
| Interfejs | Panel boczny Edge przypięty do posta + przycisk przy polu komentarza | Tłumaczenie, pomysły, szkic, wynik i uwagi nie mieszczą się w ~370 px kolumny LinkedIna (okno ze zdjęciem). Panel nie ucieka przy przewijaniu feedu. Porównanie wariantów: rozmowa 2026-11-09 i `jev_decide` (panel 0.85, panel w stronie 0.13). |
| Wybór posta (od 0.3.0) | Tryb podążania: otwarty panel pobiera post, w którego polu komentarza kliknięto. Na stronie nie ma żadnych dodatków. | Pływający przycisk z 0.1–0.2 był nakładką, a regulamin LinkedIna (§8.2, wersja z 3.11.2025) zabrania „Overlay or otherwise modify the Services or their appearance”. LinkedIn wykrywa też rozszerzenia (BleepingComputer, 3.04.2026). Przy okazji odpada jedno kliknięcie. |
| Dostawcy | Jeden klient SDK Anthropic: API Anthropic albo OpenRouter (`https://openrouter.ai/api`, endpoint zgodny z Anthropic, token Bearer) | Jeden kod dla obu dostawców, bez warstwy zgodności z OpenAI. |
| Gdzie idą zapytania | Z panelu bocznego (strona rozszerzenia) | Brak problemów z CORS. Klucz nie trafia do kontekstu strony LinkedIna. Strumieniowanie prosto do interfejsu. |
| Format odpowiedzi | Znaczniki `<comment>`, `<back_translation>`, `<notes>` itd. zamiast JSON | Tekst może się wyświetlać w trakcie generowania. Działa identycznie przez OpenRouter. |
| Myślenie modelu | Domyślne (adaptacyjne), parametr `effort` = `low` | Opus 5.5 nie pozwala wyłączyć myślenia. `low` daje szybkie odpowiedzi przy krótkich tekstach. |
| Odmowa modelu | `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) tylko dla API Anthropic | Zalecane przez dokumentację dla Sonnet 5.5 / Opus 5.5. Na OpenRouterze beta nie jest dostępna. |
| Wstawianie tekstu | `execCommand('insertText')`, potem syntetyczne wklejenie, a na końcu schowek z komunikatem | Edytor LinkedIna musi „zauważyć” zmianę, inaczej przycisk Opublikuj się nie aktywuje. |
| Styl językowy | Skróty reguł `humanizer` (EN) i `miodkuj` (PL) w prompcie systemowym, bez osobnego przebiegu. Tłumaczenie zwrotne jest wyłączone z reguł PL. | Decyzja 2026-11-09 (`jev_decide`: wariant ze skrótem reguł, pewność 1.0). Pełny drugi przebieg podwoiłby czas i koszt, a wygładzanie tłumaczenia zwrotnego zniszczyłoby jego funkcję kontrolną. |
| Cache promptu | `cache_control` na prompcie systemowym, tylko API Anthropic | ~1,8 tys. tokenów stałej części promptu. Kolejne zapytania w 5 minut płacą ~0,1× ceny. Na OpenRouterze przekazywanie tego parametru nie zostało sprawdzone. |
| Twój styl (od 0.3.0) | Lokalna historia wstawionych komentarzy (do 100) jako przykłady w osobnym bloku promptu i preferencje uczone z ręcznych poprawek | LinkedIn dopuszcza pomoc AI, gdy komentarz „represent[s] your voice” (news.linkedin.com, 20.05.2026). Bez importu starych komentarzy z LinkedIna, bo masowe czytanie strony to scraping. |
| Kontrola jakości (od 0.3.0) | Heurystyki bez modelu i osobne zapytanie `check_comment` po każdej wersji. Tylko ostrzega, nie blokuje. | LinkedIn obniża zasięg treści generycznych i odpowiedzi, które „simply restate the original post”. Reguły stylu w prompcie zapobiegają, ale nie sprawdzają wyniku. |
| Kontekst i Harmonic (od 0.3.0) | Opis autora, podlinkowany artykuł, do 3 cudzych komentarzy. Opcjonalnie publiczne fakty z Harmonic. | Lepsze dopasowanie i brak powtórzeń. Harmonic: kształt API z dokumentacji firm trzecich, bez list zespołu (brak udokumentowanego endpointu, dane poufne). |
| Grafika | Pobierana przez panel i wysyłana jako base64 | Podpisane adresy `media.licdn.com` mogą być niedostępne dla serwerów API. |

## Poza zakresem (na razie)

- Automatyczne publikowanie: celowo nigdy.
- Historia komentarzy między sesjami.
- Skrót klawiszowy „pisz po polsku w polu LinkedIna i zamień” (wariant C z rozmowy). Można dodać później jako przyspieszenie.
- Ostrzeżenie, że spółka jest na listach zespołu w Harmonic: czeka na dokumentację API list.
- Utwardzenie na prawdziwym LinkedInie (diagnostyka odczytu, zgłaszanie problemów jako przypadków testowych): kierunek 5 z analizy 2026-11-09.

## Ograniczenia i ryzyka

- **Budowa strony LinkedIna.** Selektory są listą z zapasowymi strategiami, a test E2E sprawdza je na uproszczonej atrapie. Prawdziwy LinkedIn trzeba zweryfikować ręcznie. Przy zmianach LinkedIna poprawia się listy w `src/content/linkedin-dom.js`.
- **Otwarcie panelu przyciskiem na stronie.** Przeglądarka może je odrzucić (wymóg gestu użytkownika). Wtedy przycisk pokazuje podpowiedź, a post jest już wybrany, więc wystarczy ikona albo Alt+Shift+L.
- **Identyfikatory modeli na OpenRouterze** (`anthropic/claude-sonnet-5.5`, `anthropic/claude-opus-5.5`) pochodzą z katalogów modeli. W ustawieniach można wpisać inny.
